# 数据格式

所有 JSON 使用 UTF-8。下面的文字仅展示结构，不代表完整训练数据。

## 随仓库提供的数据

`CPMK/data/` 保留原始数据目录与文件名，包含以下内容：

| 目录 | 内容 |
| --- | --- |
| `tran_val/` | 训练集、验证集及不同翻译版本的 JSON |
| `kg/` | 三份知识数据 JSON；不包含训练所需的 `images/` |
| `PI_retrieval_1/` | 检索图文数据 CSV 与图片 |
| `PI_retrieval_2/` | 500 对检索数据 JSON 与图片，默认评估使用此目录 |
| `PI_retrieval_banana/` | 合并后的检索数据 JSON 与 `banana_images/` 图片 |
| `fzk/` | 丰子恺图文 CSV 与 `ZiKai`、`ZiKai_10`、`ZiKai_14` 图片目录 |

图片和 `data/kg/` 的大型 JSON 使用 Git LFS。克隆后在仓库根目录执行
`git lfs install`、`git lfs pull` 下载实际文件；仅有 LFS 指针时不能运行评估。
数据整理未纳入旧处理脚本、Python 缓存和日志。

默认训练、验证和检索参数可直接定位到上述目录；模型权重仍需另行准备。
默认知识文件仍为同级 `KG/imagery_text_image_align.json`，不会自动改用 `data/kg/`。
这些知识文件中的图片索引不会自动转换为图片路径，训练前仍须准备意象图片。

## 训练与验证

兼容项目现有的列表格式：

```json
[
  {
    "1": {
      "诗句": "明月照山河",
      "译文": "明亮的月光照耀山河"
    }
  }
]
```

也支持按编号组织的字典；旧字段 `诗歌` 和 `翻译/译文` 会被统一转换。
编号不得重复，诗句和译文不得为空。`--max_samples` 按文件顺序限制原诗数量，
在训练集和验证集上分别生效。

## 意象知识

发布布局中，默认读取代码目录同级的 `KG/imagery_text_image_align.json`。
也可通过 `--kg_node` 指定其他文件，以下为主流程需要的字段示例：

```json
{
  "明月": [
    {
      "Meaning": "明亮的月亮",
      "tag": "明月_0",
      "image": "明月_0.png"
    }
  ]
}
```

主流程按原实验策略选择第一个释义。每个意象至少需要一个包含 `Meaning`
的节点。`image` 可省略：省略时使用 `--image_root/tag.png`；
提供时将其作为相对于 `--image_root` 的图片路径，例如
`明月/results/明月_0/明月_0_index.png`。发布数据应优先使用相对路径。

知识文件中的其他字段会保留，不参与当前训练流程。
公开知识文件的 `align`、`image_index` 不会自动映射到图片路径；
请按实际图片布局填写 `image`，或准备以 `tag.png` 命名的图片。
当前程序不生成图片，也不根据固定示例图片推断其他意象的对应关系。

分词结果在原诗中定位，位置包含 `[CLS]` 偏移。
原诗按字符编码为 `[CLS] 正文 [SEP] [PAD]...`；
被截断、只剩半个词或不是双字词的意象不进入训练样本。

## 图文检索

```json
{
  "明月照山河": {
    "translation": "明亮的月光照耀山河",
    "image": "moon.png"
  },
  "春风入故园": {
    "translation": "春风吹进故乡的园子",
    "image": "spring.png"
  }
}
```

JSON 的键是用于检索的原诗，`translation` 保留为数据说明，当前评估不读取它。
图片放在 `--retrieval_images` 目录内；未提供 `image` 时，沿用原数据的
“原诗前五个字符 + `.png`”规则。少于五个字符时使用完整诗句。

缺图、同一图片路径对应多条原诗都会直接报错，防止对角线指标中的配对错位。
评估使用 `--max_samples N` 时，仅检查前 N 条被选中的记录；
未选中记录的图片可以暂不准备。未限制样本数时仍检查全部配对。
前五字相同时必须使用不同的显式 `image` 路径。
如果实际任务是一对多检索，应另行设计相关性标注与指标，不能使用此处的一一配对指标。
